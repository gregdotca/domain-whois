# Changelog

## 2026-10-11

- Pin the indirect dependencies in `services/web/requirements.txt` (blinker 1.9.0, click 8.5.0, future 1.0.0, itsdangerous 2.2.0, Jinja2 3.1.6, and MarkupSafe 3.0.4, the versions pip resolves today). Only the four direct packages were pinned, and because the Dockerfile builds wheels with `--no-deps`, the final stage fetched the rest from PyPI at whatever version was current, so a rebuild could change them without any code change. They're now built into wheels with everything else.
- Run the tests in the production Docker build, right after flake8, in `services/web/Dockerfile`. The builder stage now installs the requirements and pytest 9.1.1, so a failing test stops the build instead of being deployed.
- Remove `gcc` from the builder stage of `services/web/Dockerfile`. Every dependency installs from a ready-made wheel or, for python-whois, a pure-Python build, so the compiler was never used. MarkupSafe has prebuilt wheels for both x86_64 and arm64.
- Tidy `docker-compose.yml`: drop `FLASK_ENV`, which Flask removed in 2.3, and `FLASK_APP`, which gunicorn doesn't read; run gunicorn directly instead of through `bash -c`; and remove the old `# version: '3.8'` comment. The container runs the same way.
- Update `CLAUDE.md`: the tests now run in the Docker build, the indirect dependencies are pinned, and the local setup pins pytest.
- Add `<!DOCTYPE html>`, `lang="en"`, and a viewport meta tag to `services/web/project/templates/home.html`. Without the doctype, browsers rendered the page in quirks mode; without `lang`, screen readers had to guess the page's language; and without the viewport tag, phones showed a zoomed-out desktop layout. The desktop view looks the same as before.
- Remove jQuery. It was loaded only to show the loading spinner (`$('#loading').show()`), which the Lookup button now does with one line of plain JavaScript. This removes `services/web/project/assets/jquery-3.7.1.min.js` and a request on every page load.
- Remove the final stage's `RUN apt-get update` from `services/web/Dockerfile`. It installed nothing, so it only added a layer and slowed the build. Also remove the commented-out netcat install above it.
- Update `CLAUDE.md` with the local `.venv` setup, the jQuery removal, and subshells around the command blocks' `cd services/web` (the relative `cd` left the shell in `services/web`, so running a second block from the same shell failed), and drop jQuery from the list of uncounted files in `ACR.md`.
- Fix lookups of punycode domains under internationalized TLDs, such as `xn--e1afmkfd.xn--p1ai` (`пример.рф`), which came back empty. python-whois finds the registered domain by matching the public suffix list, which stores IDN suffixes in Unicode, so it didn't recognise `xn--p1ai` as a suffix and looked up just the TLD. `process_domain()` in `services/web/project/__init__.py` now converts the domain to its Unicode form before the lookup. ASCII domains and domains typed in Unicode are unchanged. Sending the ASCII form instead, the other option considered, would have broken these lookups for Unicode input too.
- Add tests in `services/web/tests/test_domains.py` for `is_valid_domain()` (valid and invalid names, IDNs, malformed punycode, IP addresses, and length limits) and `process_domain()` (HTML escaping of the WHOIS response, the punycode conversion, and the error message), with `whois.whois()` stubbed out so they need no network. The project had no tests. pytest isn't added to `requirements.txt` or the Docker build; the tests are run locally.
- Remove the `form`, `justify-left`, and `loading-circle` classes from `services/web/project/templates/home.html`. They aren't Tailwind or daisyUI classes and produced no CSS, so nothing visible changes.
- Update `CLAUDE.md` with the test commands, the Unicode lookup, and the removed classes.
- Update `ACR.md` and the README badge from B2b to B3b. With the AI-written tests and lookup fix, AI wrote just over half of the code lines (163 of 313, or 127 of 217 without blank and comment lines), which puts the AI Share at 51–75%. The oversight level stays at Reviewed.
- Update `ACR.md` and the README badge from B1b to B2b. With the AI-written CSS build, dark mode, and earlier changes, AI wrote about a third of the code lines (73 of 223, or 58 of 148 without blank and comment lines), which puts the AI Share at 26–50%. The vendored daisyUI and jQuery files aren't counted. The oversight level stays at Reviewed.
- Add `aria-label="Domain"` to the domain input in `services/web/project/templates/home.html`. The input had only a placeholder, which screen readers don't reliably announce as its name, and which disappears once the field has a value (it's pre-filled with the current domain). The label matches the placeholder, so nothing visible changes.
- Add automatic dark mode, following the visitor's system setting, with no toggle or JavaScript. `services/web/project/styles/app.css` adds daisyUI's `business` theme with `--prefersdark`, which applies it under `@media (prefers-color-scheme: dark)` on `:root:not([data-theme])`, so `home.html` drops `data-theme="bumblebee"` from `<html>`, which would have locked the page to the light theme. `home.html` also gets a `color-scheme` meta tag so the browser knows about both modes before the CSS loads. In dark mode the Lookup button uses `btn-primary` instead of `business`'s orange accent, with a darker navy primary, `oklch(34% .085 251.473)`, than the theme's own (text on the button is 8.3:1), and the corners use `bumblebee`'s radii, so the form doesn't turn nearly square. These overrides are an unlayered rule at the end of `app.css`, so they beat daisyUI's layered theme. Update `CLAUDE.md` to match.
- Build the CSS locally with the Tailwind standalone CLI instead of loading Tailwind and daisyUI from the jsDelivr CDN. The page depended on a third-party CDN at runtime, and Tailwind's browser build generates the styles in the visitor's browser with JavaScript. The builder stage of `services/web/Dockerfile` now downloads Tailwind v4.3.3, checks it against the release's SHA-256 for the machine's architecture, and compiles the new `services/web/project/styles/app.css` into `project/assets/app.css`, which the final stage copies in. The file is gitignored. daisyUI 5.7.46 is vendored as `project/styles/daisyui-5.7.46.mjs`, checked against the release asset's SHA-256, with only the `bumblebee` theme enabled. `bumblebee` is identical in 5.7.46 and in the 5.0.0 `themes.css` the page loaded before, so the page looks the same. `home.html` now loads `/assets/app.css`. Update `CLAUDE.md` to match.
- Validate the domain before looking it up. `process_domain()` in `services/web/project/__init__.py` passed any text from the URL to `whois.whois()`, so things like `google` or `8.8.8.8` were sent to WHOIS servers and came back as empty results. The new `is_valid_domain()` accepts domain names, including internationalized ones like `münchen.de`, and rejects malformed punycode (`xn--`) labels. Anything else gets a "Please enter a valid domain name" message without a lookup. The form also trims spaces around the submitted domain. Update `CLAUDE.md` to match.
- Fix the Docker build's style warnings in `services/web/Dockerfile`: use `AS builder` instead of `as builder`, and `ENV KEY=value` instead of the legacy `ENV KEY value` form.
- Pin the daisyUI and Tailwind CDN URLs in `services/web/project/templates/home.html` to exact versions (`daisyui@5.7.47` and `@tailwindcss/browser@4.3.3`, the versions `@5` and `@4` resolved to on jsDelivr today). The open-ended `@5` and `@4` URLs picked up each new release without warning, so an upstream change could alter or break the page. daisyUI's `themes.css` stays at 5.0.0, as before, so the page looks the same.
- Fix the install step in `README.md` to use `docker compose` instead of the old `docker-compose` command.
- Update `CLAUDE.md`: fix a grammar slip in the lookup description, note that `is_valid_domain()` rejects malformed punycode and that `whois.whois()` gets the domain as typed, note that `Dockerfile.DEV` pins the same base image and skips flake8, add the dev run command, and list the pinned CDN versions.
- Update `ACR.md` and the README badge from B1a to B1b, and set the `updated` date. The AI agent also wrote the domain validation, which the maintainer reviewed but didn't verify line by line, so the oversight level drops from Verified to Reviewed. The AI Share stays at 1–25%.

## 2026-10-10

- Upgrade Python from 3.9.21 to 3.14.8 in `services/web/Dockerfile`, since Python 3.9 stopped getting security updates in October 2025.
- Upgrade Flask from 2.3.0 to 3.1.3, Werkzeug from 2.3.0 to 3.1.9, and gunicorn from 20.1.0 to 26.2.0 in `services/web/requirements.txt`, to pick up their security fixes, including gunicorn's fixes for HTTP request smuggling.
- Keep python-whois at 0.8.0. The latest release, 0.9.6, looks up each TLD's WHOIS server in the IANA registry, which no longer lists one for `.uk`, so lookups like `bbc.co.uk` failed. 0.8.0 still works on Python 3.14.
- Upgrade flake8 from 3.9.1 to 7.4.1 in the Docker build, since 3.9.1 doesn't support Python 3.14.
- Start gunicorn with `--no-control-socket` in `docker-compose.yml`. gunicorn 26 opens a control socket under the app user's home directory by default, which the app user can't write to, so it logged a permission error at startup. The app doesn't use the control socket.
- Update `CLAUDE.md` with the new versions and the python-whois pin.
- Update the "How AI Was Used" section of `ACR.md` to say the AI agent also wrote these upgrades. The rating stays B1a, since the AI-written code is still under 25% of the project and the maintainer verified every line.
- Fix a cross-site scripting (XSS) hole in the lookup page. `process_domain()` in `services/web/project/__init__.py` put the raw WHOIS response into the page, and `home.html` outputs it with `|safe`, so HTML or a script in a WHOIS server's response ran in the visitor's browser. The response is now HTML-escaped before newlines are turned into `<BR>` tags. Update `CLAUDE.md` to match.
- Update `ACR.md` and the README badge from B0a to B1a, since the AI agent wrote the XSS fix, which is the first AI-written code in the project. The maintainer verified every line of it.
- Add `CLAUDE.md` with build, lint, and dev/prod switching commands and an architecture overview, so Claude Code can work in the repository without rediscovering how it's set up.
- Update the copyright notices in `LICENSE` and `README.md` to `2024-2026` and add the contact email, so they match the current year and the standard notice format.
- Fix the installation instructions in `README.md` to load the app over `http://`, since the production container serves plain HTTP on port 8094 and has no TLS.
- Add `ACR.md` with an AI Code Rating of B0a, and an ACR badge at the top of `README.md`, to disclose that the code was written without AI (an AI agent has helped only with documentation, which the rating doesn't count).
